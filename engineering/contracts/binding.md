## 1. Scope

How a session becomes bound to a printer, what the binding state is at any moment, and what every consumer does with it. Owner: `sessions`. List source: `printer` (the printer-state contract). Consumers: `mcp` (tool gate), `server` (binding reads and the manual-bind write on the user routes), `ui` (binding control and printer-dependent controls). Covers the edges `sessions → printer` (list reads + freshness subscription), the binding reads on `mcp → sessions` and `server → sessions`, and the `bind` write on `server → sessions` alone — the agent has no bind tool; it asks the user (§4). The cross-seam conventions (`conventions.md`) apply to every operation here.

## 2. The model: one write, everything else derived

- **The stored binding** — the binding's persistent decision state: the bound name, the manual flag, and the bind's position in the session's intake order (so "uploads after the bind" is well defined). Written by exactly two acts — `bind` (manual) and auto-bind (below) — and never changed by list changes. The only other binding-owned persistent state is the emitter's last-announced derived output — the comparison baseline the cross-restart emission rule requires, and the value reads serve while an input is transiently unreadable (the failure arm's rule).
- **The inputs** — besides the stored binding, the derivation reads: the newest named `.3mf` upload *postdating* the stored binding (its printer name per the evidence contract's name read; a bind acknowledges everything before it, and with no stored binding the cut-off is the session's creation, so every named upload counts), and `printers()` — the serving list with its freshness, where the retained list *is* the last successfully interpreted content (the printer-state contract), so "what the document says" is always the retained list and "whether that is current" is its freshness.
- **The derivation** — `binding(session)` computes the reported state from those inputs at every read; nothing is completed, applied, or queued, so the state is current by construction while every input serves — the one exception is a transiently unreadable input, where reads serve the last-announced state instead (the failure arm below). The closed set every consumer maps (meeting an unmapped state is a defect by definition):
  - **bound(canonical, manual?, note?)** — the stored name resolves uniquely on the retained list (§3), displayed under its canonical; a stored name with no judgment yet displays verbatim — never-judged for any reason, whether no retained list exists or the name was stored while the list was unreadable; nothing served to judge it against.
  - **bound-but-missing(name, note?)** — the stored name resolves to nothing on the retained list.
  - **bound-but-ambiguous(canonical candidates, note?)** — the stored name is an alias of several printers on the retained list; candidates are always canonical names (only canonical names name printers distinctly).
  - **unbound(note? | candidates?)** — no stored binding, and no post-bind named upload awaits a conclusion.
  - **pending-evaluation(cause)** — no stored binding, a post-bind named upload exists, and its outcome cannot be concluded yet: a negative or ambiguous conclusion needs a Fresh list (concluding absence from a stale list would misfile the just-added-printer upload, the exact failure R3 forbids), and a missing input defers everything — no list at all, the list query's error arm, or the upload's name unreadable (the evidence contract's read error). The cause names the *blocking input*: the current freshness cause where the list is the blocker, the transient list-unavailability where the query itself fails (no freshness is readable through a failed query), and the name-read failure where the name is the blocker — with precedence when several block at once: the name-read failure first, since it is the blocker most specific to the upload and survives every list state, else the list-side cause — always an input actually in the way, so the remedy a consumer renders can work (R10).
- **Auto-bind** — the one derived write: when the session is unbound or auto-bound — *auto-bound* meaning any stored binding whose manual flag is unset, whatever family it currently reports, so a non-manual session parked in bound-but-missing or bound-but-ambiguous auto-recovers too — and the newest post-bind named upload resolves uniquely on the *serving* list (Fresh, or the retained list behind Pending — binding is a positive act, and last-known-good supports it), `sessions` stores that canonical with the manual flag unset. On an auto-bound session a later unique resolution to a different printer re-binds the same way. A manual binding is never overwritten by any derivation — a non-confirming upload outcome is visible as the derived note instead.
- **Annotations are derived, never stored**: the note or candidates describe the newest post-bind named upload's standing against the current inputs — a no-match note or canonical candidates on an unbound session (concluded against Fresh), and on a session with a stored binding — bound, bound-but-missing, and bound-but-ambiguous alike — a mismatch note naming that the upload's name resolved elsewhere or nowhere, concluded against Fresh like every negative: until a Fresh list serves, the bound-family session simply carries no new note — the binding stands, nothing misfiles, and no transient false mismatch ever shows. They refresh whenever the inputs change and cannot go stale by construction; a new bind moves the cut-off, which is how binding clears them.
- **Emission**: `sessions` re-derives on every input change — an upload commit, a bind, a freshness event (the `sessions → printer` subscription), and recovery of a previously failing input via the conventions' bounded re-attempt — and emits the binding-changed durable event (state-bearing, per the events contract) with a transcript *trace note* exactly when the derived output differs from the last one announced — the trace note accompanies every announced change, distinct from the closed set's annotation field, which exists only when an upload's outcome left one. That rule spans restarts: a state whose inputs changed while the service was down is announced at startup, and a restart that changes nothing announces nothing. A completed `bind` or auto-bind commits its own announcement — the last-announced state updates with the write, so reads immediately serve the new binding even while other inputs are unreadable, never the pre-bind state. The current state lives only in the binding; the transcript holds history, never state (the *trace rule*: changes are noted, state is never transcribed).
- **`bind(session, printer_name)`** — never refuses a name: a supplied name the serving list resolves uniquely (§3) stores canonically; every other case — unknown name, ambiguous name, no list at all, or a serving list unreadable right now — stores the name verbatim without blocking, and the derivation reports the consequence honestly from the current inputs (missing, or ambiguous with a choice offered, as soon as a retained list judges it). A successful `bind` sets the manual flag. Its synchronous rejections: a name empty after trimming (there is nothing to store), and the conventions' unknown-session.
- **Failure arm** — scoped to the binding store itself (the persisted state unreadable, the bind unwritable): the conventions' structured, retryable error, never a coerced state from the closed set — guessing `unbound` would have the agent ask the user to bind a bound session, and guessing `bound` would delegate on unknown state (a failed manual bind is a user's click and must say why). A `printers()` or name-read fault is never this error: it defers *new* conclusions and erases nothing — the last-announced state (which emission already keeps, above) is what reads serve while an input is unreadable, so a standing binding keeps reporting its bound family and a pending session its pending state; re-derivation resumes when the input serves again. Deletion destroys the session's binding state with it, per the conventions: nothing re-derives, writes, or emits for a deleted session.

## 3. Name resolution

One rule for every path that resolves a name (the derivation, auto-bind, and `bind` alike): case-insensitive, whitespace-trimmed equality against a list's canonical names and aliases, with *canonical precedence* — a name equal to a printer's canonical name resolves to that printer outright, and alias matching applies only otherwise, so ambiguity is always among aliases and every offered candidate pick lands (candidates are canonical names, and a canonical always resolves to its owner even where it doubles as another printer's alias). A name empty after trimming is not a name: a `.3mf` carrying none, or a blank one, contributes nothing to the derivation — no note, no pending state; `bind` rejects it synchronously (§2).

## 4. Consumer mapping

Every consumer maps *every* reported state; meeting an unmapped state is a defect by definition.

| `binding()` says | `mcp` printer tools & snapshot | `server` webcam/snapshot routes | `ui` |
|---|---|---|---|
| bound (note or not) | delegate to the reported name — the canonical where the retained list judges it, the stored name verbatim where no list yet exists (printer-state's unknown-printer error answers a verbatim name honestly) | delegate | controls live; note shown if present |
| unbound (with note or candidates) | structured not-bound error carrying the note or candidates when held (the agent asks the user by name; the note is how anyone learns why the last `.3mf` failed to bind) | envelope naming the state, note or candidates included | bind offered; note or candidates shown; printer controls absent |
| pending-evaluation | structured pending error carrying the cause — retryable, never "ask the user to bind" | envelope naming the pending state and cause | pending rendering with the cause; bind still offered; printer controls absent (no printer is confirmed) |
| bound-but-missing | structured error naming the missing printer, note included when held | envelope naming the missing printer, note included | removed-printer state naming it; re-bind offered; note shown if held; printer controls absent |
| bound-but-ambiguous | structured error carrying the canonical candidates, note included when held | envelope carrying the candidates, note included | choice prompt; picking one binds; note shown if held; printer controls absent |

Gates are enforced at `mcp` and `server` — a disabled UI control is never the protection, since another device can always hit the route. The `server` column's scope is complete as listed because the webcam-list and snapshot routes are the *only* session-scoped user routes that touch a printer: user-visible telemetry arrives as transcript tool results (gated at `mcp`) and on the printers screen (session-independent), so R3's no-telemetry-for-unbound criterion holds by there being no route to gate. The table is the *binding* precondition only: a delegating row composes with the printer-state contract's own verdicts, which independently govern what a bound session's printer can actually do (NoTelemetry, Unreachable, agent print-gating, and the unknown-printer error — reachable whenever the reported name is not on the serving list, as after a verbatim bind — relayed as the structured condition it is, with the remedy the binding state names: re-bind where the retained list judges the name missing, wait where the binding is simply newer than the list) — "controls live" never overrides any of them.

## 5. Test obligations (integration)

Cells assert coverage; behaviour is specified in §§2–4. "S*n*" points into the scenario list below.

| Operation / behaviour | Injected fault | Stall | Race | Restart | Unknown session | Error distinctness |
|---|---|---|---|---|---|---|
| `binding()` read | binding-store fault → structured error, never a coerced state, rendered as the failure surface by every consumer | store stall resolves within bound | n/a — read | derived state survives; S4 | rejected | failure arm ≠ any binding state |
| `bind` write | store fault → structured error, nothing committed; a *list* fault never blocks — stores verbatim (S5) | within bound | two concurrent binds land whole in some order — no blend, events in commit order | crash mid-bind: prior or completed, event and note all-or-nothing | rejected | empty-name rejection ≠ unknown-session ≠ store fault |
| auto-bind + re-derivation | `printers()` or name-read fault defers new conclusions; last-announced state serves throughout — a bound-but-missing session still reports missing during the fault | within bound | a bind racing a Fresh arrival derives one coherent final state | crash between upload commit and first re-derivation: the upload always has a derivable standing; S4 | after deletion nothing re-derives, writes, or emits — asserted with a deletion racing a Fresh arrival | pending causes per S3 |
| emission | live input fault: the owner's bounded re-attempt re-derives without a restart | n/a — a side effect of the operations above, bounded by their stalls | one Fresh arrival changing resolution and annotation together → one state, one event, one note | a state changed while down announces at startup; a no-op restart announces nothing | nothing emits for a deleted session | n/a — no error surface of its own |

Scenarios:

1. Resolution matrix against a Fresh list: unique/ambiguous/none × unbound/auto-bound/manually-bound — auto-bind and re-bind on unique resolutions; the manual binding standing with a derived mismatch note on unique-different; negatives yielding note or candidates on unbound and notes on the bound family; alias matches canonicalized; case and surrounding-whitespace variants resolving identically; canonical precedence — a name that is one printer's canonical and another's alias resolves to its canonical owner, and a candidate pick lands even when the picked canonical doubles as another printer's alias (the pick that must never loop); every derived change with its event and trace note, and no change with neither (all asserted).
2. The Fresh-only negative rule: a `.3mf` naming a just-added printer, uploaded while the retained pre-edit list serves as Pending, reports pending and binds on the Fresh arrival — never unbound-with-note (the R3 misfiling case); a positive match against the same Pending list binds immediately; the same Fresh-only rule on a bound session — a non-matching upload under a Pending list produces no mismatch note until the Fresh arrival, never a transient false note (all asserted).
3. Pending causes name the blocking input: each freshness cause carried verbatim while the list blocks (unset-location distinguishable from credentials-missing); the transient list-unavailability under an injected query fault; the name-read failure under an injected name-read fault *whatever the freshness state* — never a freshness cause when the name is the blocker; a freshness-cause change under a standing pending session updates the reported cause with its event (the fresh-install unset→credentials transition, on a connected consumer); recovery of each blocked input concludes the derivation without user action or consumer read — via the freshness event and via the owner's bounded re-attempt (all asserted, per input).
4. Derivation currency and restarts: a document edit adding the missing printer auto-binds the unbound-with-note session and clears an auto-bound session's stale mismatch note, each with event and trace note; candidates refresh when a Fresh list changes the candidate set — on unbound and bound-but-ambiguous alike; a non-manual bound-but-missing session re-binds automatically when a later upload's name uniquely resolves, and a non-manual bound-but-ambiguous session likewise when the resolution becomes unique (both asserted); a rename keeping the bound name as an alias re-reads canonically with event and trace note; an auto-bind moves the cut-off like a manual bind — annotations from the uploads it acknowledged never linger (asserted); missing appears only from a retained list lacking the name as canonical and alias, clears when one carries it, both emitting on a connected device with no user action; freshness leaving Fresh changes no bound session's reported state; a bound-but-missing session still reports missing from a fresh instance serving the retained list as Pending (the two-R3-criteria intersection); a verbatim bind stored under a Pending list, restarted into an instance whose retained list lacks the name, reports bound-but-missing from startup with its event and note; a crash between an upload's commit and the first re-derivation leaves the upload with a derivable standing after restart — its binding consequence lands, never silently skipped (all asserted).
5. Manual bind, never refused: a uniquely-resolvable name (canonical or alias, against the serving list) stores canonically; an unknown, ambiguous, listless, or list-faulted name stores verbatim without blocking or refusing; the verbatim name reads back immediately as bound — never the pre-bind state, a bind during an injected list fault included (asserted) — then reports missing or ambiguous-with-choice as soon as a retained list judges it, and canonically once a Fresh list carries it uniquely; a re-bind that only flips the manual flag emits its event and note; a bind changing nothing at all emits nothing; the bind cut-off — uploads predating a bind contribute no annotations after it (all asserted).
6. Consumer mapping completeness: every reported state × every consumer per the table — notes and candidates reaching the agent and the user wherever held, pending never presented as unbound, and a delegating row composed with each printer-state verdict (NoTelemetry, Unreachable, gating refusal, unknown-printer) yielding that verdict's outcome, never an override; a verbatim binding with no retained list delegates the stored name, and printer-state's unknown-printer answer is relayed with its remedy (asserted).
7. The trace rule's negative half: no transcript entry ever carries binding *state* — traces record changes, the state lives in the binding alone (asserted).
