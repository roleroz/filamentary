## 1. Purpose

The R2.1 backend boundary, per the architecture: conversations, streaming, failure and retry behaviour, backend lifecycle, credential-source determination. The public surface is the message-lifecycle contract's `agent.*` operations and sink events; this document covers the sidecar, the ACP client, and the persistence behind them.

## 2. Internals

- **Sidecar manager** — spawns the pinned, vendored `claude-agent-acp` under the Node runtime, speaking ACP (JSON-RPC over stdio) through the official Rust SDK. Credential-source determination happens at spawn, because the sidecar's environment is fixed then: a present `CLAUDE_CODE_OAUTH_TOKEN` is passed through and recorded as the source in play; otherwise `~/.claude` is probed and recorded — and the record is a *content fingerprint* of the probed material (the probe's file set is a release item), not mere presence, so a re-login that rewrites `~/.claude` in place is a differing probe outcome and triggers the recycle R2.2 requires. A probe that itself faults — permission denied, an I/O error — is the fault class naming the path, classified internal fault, never folded into no-credentials (the conventions' credential fault-vs-validity split); the same holds at a recycle re-probe: the triggering attempt fails with that classification and no recycle proceeds on unknown credential state. The record is what auth failures are attributed to, and why replacing the token requires a restart while `~/.claude` fixes need at most a recycle. The sidecar spawns on first need; the attempt that discovers a spawn failure — send and `interpret_document` alike — classifies it by shape: the credential classifications for credential shapes (R2.2's fresh-install criterion depends on `no-credentials` with both remedies reaching the user), internal fault otherwise. A failed spawn leaves no standing bar to recovery: spawn attempts are single-flight, every subsequent user attempt re-attempts one when none is in flight — which is what makes each classification's retryable promise satisfiable for non-credential failures too — a send or retry *on an established mapping* arriving while a spawn or recycle attempt is in progress rejects synchronously as backend-restarting (unavailability known at send time, per the contract's line) — the creation-context send is the carve-out: it never rejects for backend state, accepting availability-independently per the contract, its conversation establishment simply queuing behind the attempt — and a resume-fire arriving mid-attempt defers, re-checking when the attempt resolves. `backend-unavailable` is reserved for a backend that *was* up and died mid-turn, per the contract's definition — a spawn that never came up is not that.
- **Recycle** — kill and respawn the sidecar, then `session/load` each affected live session (cross-process session persistence is a release item). Trigger: the next *session* attempt after an auth or no-credentials classified failure re-probes the credential sources; a probe outcome differing from the spawn record triggers the recycle before that attempt (`interpret_document` never participates — its per-attempt process needs no recycle) — which is what makes CLI login work with no service restart (R2.2), the environment token excepted per its restart rule. A recycle severs every live session on the one shared sidecar: sessions without a turn in flight are reloaded with nothing user-visible, and every turn in flight terminates with the *interrupted* classification — exactly the bound the contract's recovery-isolation invariant sets (a visible, retryable interruption, never more). A `session/load` that fails for one session severs nothing further: the failure is logged, the session's map row stands, other sessions' reloads proceed, and that session's next attempt re-drives the load — succeeding, or failing that attempt with the load failure's shape classification. A recycle is never triggered by a per-call content problem.
- **Session map** — persisted table: session ↔ ACP session id, the id *optional* — a mapped session whose conversation is not yet established holds none. The creation-context first `agent.send` provisions via `mcp.endpoint_for` and records the row before acceptance (a provisioning fault is that send's synchronous rejection), then establishes the conversation where the sidecar is available; where it is not — the fresh install above all — the send still accepts against the recorded row and the turn fails with its classification asynchronously, per the contract's availability-independent acceptance, a later attempt establishing the conversation (`backend_state` answers Exists from the row, distinct from never-sent). Establishment picks its call by the row: `session/load` where an ACP id exists, `session/new` where none does — a mapped session whose conversation was never created is new, not loadable. The endpoint is never persisted: `mcp.endpoint_for` is re-read (idempotent) at every conversation establishment — `session/new` and each `session/load` — so the URL carries the current configured address by construction; it rides the ACP session's `mcpServers` as a streamable-HTTP server (adapter acceptance is a release item). Teardown tombstones the row, per the contract — a later send for the session draws unknown-session, never a re-creation. An ACP conversation is established once per session per sidecar process: `session/new` at creation, then `session/load` re-establishes it — *eagerly* for every affected live session during a recycle (the Recycle bullet's batch), *lazily* on a mapped session's first attempt after an ordinary service restart or a spawn-on-first-need — so a reopened session continues with its history (R4, R2.1) whichever event replaced the process; a load failure on the lazy path surfaces as that attempt's shape-classified failure, re-driven by the next attempt like any spawn-path failure.
- **Pending message store** — persisted rows *per (session, message key)*: (key, full content including image bytes — the contract's retry rule requires re-sending the persisted message intact, bytes included — instructions, state: accepted | completed-succeeded | completed-failed, landed flag). One row serves the contract's two retention duties, whose lifetimes differ: the *backstop* — an unlanded row restores its user-message entry after a crash; `message_landed` sets the flag and never deletes by itself — and the *retry source* — a completed-failed row not marked superseded is the one standing failed message `retry` re-sends (at most one stands: a later accepted *send* marks every earlier failed row superseded — a durable flag, so a superseded row deleted-newer-rows cannot resurrect — while a retry or an automatic resume is not a new message at all: each flips the standing failed row itself back to accepted, reusing its key and content, which is why the resumed turn's sink events correlate to the original user-message entry and no second `message_landed` is ever owed). A row is finalized — its terminal outcome trusted for deletion — only once `turn_landed` confirms the terminal entry committed, per the contract: a landed completed-succeeded row deletes at its confirmed terminal, a landed superseded failed row at its supersession — an unlanded row never, whatever its state; a terminal emitted but never confirmed is re-synthesized at startup with its recorded outcome, `sessions` deduplicating by message key against its committed terminal entries. `pending_message` serves the oldest unlanded row; restoration drains by repeated call-and-land, deterministic and terminating because each landing clears one row and exposes the next.
- **Startup turn recovery** — at startup, a pending row found accepted-but-not-completed is a turn Filamentary's own restart cut short: `agent` marks the row completed-failed and synthesizes its `Failure` sink event with the *interrupted* classification (cause and remedy), ordered after the restored user-message entry per the recovery-ordering rule — the marking is what makes the promised retry reachable. `sessions`' turn-in-flight flag is the terminal's idempotence guard: a synthesized terminal for a session not flagged in-flight is dropped there (the real terminal already landed — the crash fell between `sessions`' terminal commit and this row's marking), and one for a session with no committed row is dropped like any event for a session that does not exist, the creation-journal unwind then clearing the row. This — not recycle — is how a bare service restart produces `interrupted`.
- **Resume scheduler** — persisted (session, fire-at) rows driven by an injected clock; fires only when no turn is in flight, is superseded by any user send/retry (which deletes the row), re-arms on a fresh usage limit, and fires immediately at startup for elapsed times; the row is consumed at fire — its deletion committing in the *same store transaction* as the resume's acceptance, which is the standing failed row flipping back to accepted (no new row, no new key — the fire is a retry in everything but initiator), crash-atomic per the conventions — so an arming fires at most once, with no crash window that double-fires. The schedule-row write happens as part of processing the usage-limit terminal, and a write fault fails whole per the conventions' live-persistence rule — no in-memory fallback, no undeclared re-drive: the terminal takes the contract's unarmed shape (the failure entry carries the parsed reset time and says the automatic resume is not armed, manual retry standing — the arming clause the contract's automatic-resume bullet defines), and the fault is logged. A later attempt hitting a fresh usage limit re-arms normally.
- **Classification mapper** — maps the sidecar's error shapes to the contract's classifications, including the usage-limit reset-time parser; a shape the mapper does not recognize is *internal fault*, never a crash. The real shapes are release items; the mapper is table-driven so re-recording updates data, not logic.
- **Sink relay** — translates ACP `session/update` notifications into the contract's sink vocabulary, relaying tool-result payloads structurally; kinds outside the vocabulary are dropped and logged (the real kind set is a release item). The terminal and resume events are synthesized, not translated: `TurnEnd`/`Failure` at the turn's classified terminal, `ResumeFired` by the scheduler at fire — all entering the same ordered sink stream as the translated events.
- **One-turn lock** — per-session in-process lock; acceptance takes it, terminals release it. Turns on different sessions run concurrently (a release item verifies the sidecar supports it).
- **`interpret_document`** — a one-shot ACP session on its *own short-lived sidecar process*, spawned per attempt with freshly determined credentials and torn down after; no `mcpServers`, no persistence; a restart abandons it. The separate process is what makes recovery isolation structural — an interpretation failure of any class touches no session and triggers no recycle — and what satisfies R3's no-restart credential pickup for the `~/.claude` source: the next attempt simply spawns against the current material; the environment token follows its restart rule (the service's own environment is fixed at process start), like everywhere else. This module owns the interpretation prompt template and the reply parser (the operation returns `Result<Printers, Error>`): an unparseable reply is the malformed-output classification — never `interrupted`, and never a recycle trigger, since it is a per-call content problem. A spawn failure surfaces through this operation as the call's shape-classified failure (its per-attempt process makes every failure per-call).
- **Teardown** — ordered idempotent steps over the tables plus `mcp.revoke`; each step tolerates already-done. During the session's own in-flight turn it releases the lock, terminates the ACP session, and produces no entries — subsequent sink events for the session are dropped per deletion permanence.
- **Session existence** — an operation addressing a session with a tombstoned map row, or with no row outside the creation-context send, draws the conventions' unknown-session error, with the contract's declared exceptions this module owns: `backend_state` answers its definite `None`; `teardown` is cleanup — idempotent clean completion for an unknown session, never an error, which keeps the deletion cascade re-drivable (`mcp.revoke`'s matching exemption is `mcp`'s own); and the landing confirmations, `message_landed` and `turn_landed`, complete cleanly on a *live* session whose matching row is already cleared or finalized — their idempotence includes the already-done case, so `sessions`' bounded re-drives always terminate — while a torn-down session draws unknown-session like any operation.

## 3. Interface

Public: the message-lifecycle contract's operations and sink. Module-private, each injectable for tests: the sidecar manager's spawn/recycle API, the classification table, the persisted store behind the session map / pending messages / resume schedule, the clock, the credential probe, the `mcp` client (`endpoint_for`/`revoke`), and the sink itself (an in-process ordered channel to `sessions` — delivery is process-internal, so its only failure is process death, covered by the startup recovery and `turn_landed` re-synthesis; it has no independent failure modes to enumerate).

## 4. Error handling and failure visibility

Every sidecar and store fault becomes a classified failure or a structured error arm per the contracts — never a panic, never silent. Visibility per mode: spawn failures surface as the discovering attempt's classified failure naming the credential source where relevant — send and `interpret_document` alike; a sidecar crash mid-turn classifies backend-unavailable and logs the process exit, and a crash while idle logs the exit too, with no phantom failure entries; protocol violations (malformed frames) classify protocol and log the frame; dropped update kinds log the kind; store faults surface on the calling operation's error arm and log the operation; an `mcp` provisioning or revoke fault logs the operation and session alongside its structured surface; `interpret_document`'s failures — spawn, classification, malformed output — log under the interpretation call's own correlation (operation and attempt), the call being sessionless; a restart-interrupted turn surfaces as its synthesized interrupted failure entry — never silently absent. All logging is reported through `server`'s logging facade (the service log is `server`'s) with session and message key where the operation has them.

## 5. Test plan

Contract tests (`test_contract_*`), unit level, against a scripted fake sidecar and stateful store fakes:

1. Classification mapping: each recorded error shape maps to its classification with cause and remedy content; the reset-time parser's parseable and unparseable cases; an unknown shape maps to internal fault.
2. Sink relay: each vocabulary kind translates with payload intact (tool results structural, never flattened); an out-of-vocabulary kind is dropped and logged.
3. Pending message lifecycle: written at acceptance with image bytes, the terminal outcome recorded at completion, restored byte-identical after a simulated restart; the dual retention asserted — a landed completed-failed row *persists* as the standing failed message and post-restart `retry` re-sends it intact (bytes included), a landed completed-succeeded row deletes at its `turn_landed`-confirmed terminal (and survives an unconfirmed one), a landed superseded failed row deletes at supersession, and an unlanded row survives every state (asserted per case); two unlanded rows drain by repeated `pending_message` call-and-land in acceptance order (asserted); at most one standing failed row — a later accepted send marks earlier failed rows superseded durably (a failed-A, send-B, B-succeeds sequence leaves nothing to retry — asserted), and retry or a resume-fire flips the standing row itself back to accepted reusing its key, the resumed turn's events correlating to the original entry (asserted); a success terminal synthesizes `TurnEnd` into the sink (asserted); `backend_state` answers its two-valued set (Exists/None) definitely across the contract's four restart scenarios — never-sent, accepted-pending, accepted-completed, torn-down — while `pending_message` answers pending/none for live sessions and draws unknown-session for torn-down ones (the contract's split, asserted distinct).
4. One-turn lock: concurrent send/retry/resume against one session — exactly one accepted, busy/nothing-to-retry rejections correct; two sessions proceed concurrently.
5. Resume scheduler: fires at time, late after downtime, supersession (row deleted), re-arm, never into a running turn, no-schedule without a parseable time, and at-most-once per arming — the row's consumption committing atomically with the resume's acceptance, a crash injected between them finding either both or neither, never a second fire (injected clock and crash points, asserted).
6. Credential-source determination: token present → token recorded and attributed; absent → probe result recorded; the no-silent-fallback rule (a rejected token never triggers a `~/.claude` attempt).
7. Recycle: every live session reloaded, each in-flight turn interrupted visibly, idle sessions showing nothing user-visible (asserted on both kinds); one session's `session/load` failing leaves its map row standing and the other sessions reloaded, its next attempt re-driving the load — succeeding when the fake recovers, classified by shape when not (asserted).
8. Teardown: idempotent per step, complete from every partial state, `backend_state` = None after; on a never-created and an already-torn-down session it completes cleanly as the cleanup exemption — never unknown-session (asserted).
9. Endpoint wiring and conversation establishment: `endpoint_for` re-read at every establishment — `session/new` at creation and each `session/load` — the carried URL asserted current after a simulated config address change (never the stale address); a mapped session's first attempt after a simulated restart runs `session/load` before prompting (asserted on the fake's frames) — a load failure there classifies by shape and the next attempt re-drives it.
10. Interpretation: the recorded reply shape parses to `Printers`; an unparseable reply classifies malformed-output — no recycle, no `interrupted`, other calls untouched; a recorded availability failure of *any* class (auth included) triggers no recycle and touches no session (asserted); the per-attempt spawn picks up changed `~/.claude` credentials with no recycle (asserted; the environment token is fixed at process start per its restart rule and is not in this test's domain); a simulated restart abandons the call with nothing persisted.
11. Prompt shape at the backend seam: the assembled ACP prompt carries exactly the given text, image refs as image content blocks *labelled with their identifiers* (the evidence contract's citation rule), file refs as their named handles only, and the instructions — asserted on the fake sidecar's received frames.
12. Session existence and confirmation idempotence: retry, `message_landed`, `turn_landed`, and a send against a torn-down (tombstoned) session each draw unknown-session; `backend_state` answers `None`; sink events for a torn-down session are dropped; a repeated `message_landed` or `turn_landed` on a live session whose row is already cleared or finalized completes cleanly — never an error, the re-drive terminates (asserted per confirmation) — (`endpoint_for`'s unknown-session behaviour is `mcp`'s obligation, tested there; a no-mapping send is the creation context per the contract's caller invariant, covered by test 9).
13. Startup turn recovery: a simulated restart with an accepted-but-not-completed row marks it completed-failed and synthesizes the interrupted failure — cause and remedy present, ordered after the restored user-message entry, retry re-sending the persisted message (asserted); a completed row whose terminal was confirmed by `turn_landed` synthesizes nothing, while one never confirmed re-synthesizes its recorded terminal (asserted distinct); a send or retry mid-spawn-attempt rejects backend-restarting while a resume-fire defers and re-checks at the attempt's resolution (asserted on both); a creation-context send with the sidecar unavailable accepts against the recorded mapping and the turn classifies asynchronously — `backend_state` answering Exists — with a later attempt establishing the conversation (the fresh-install path, asserted end to end at this seam).
14. Recycle trigger: an auth failure with `~/.claude` in play, followed by the probe finding changed credentials, recycles before the next attempt and it succeeds — no restart; a token-source failure never triggers the probe path (asserted).
15. Teardown mid-turn: the turn ends without entries, the lock releases, late sink events drop, `backend_state` = None.

Failure-mode tests (`test_failure_<dependency>_<mode>`):

- sidecar process: `spawn_failure` (the discovering attempt classifies by shape — internal fault for a missing binary, the credential classifications for credential shapes; the next user attempt re-attempts the spawn and succeeds once the fake recovers — retryable for the non-credential class too, asserted; a send arriving mid-spawn-attempt rejects synchronously as backend-restarting), `crash_mid_turn` (backend-unavailable), `crash_idle` (next send classifies, no phantom failures), `unparseable_frame` (protocol).
- credential probe: `io_fault` (internal fault naming the path — never no-credentials), `io_fault_at_recycle_reprobe` (the triggering attempt fails with the fault classification and no recycle runs — no session severed on unknown credential state, asserted).
- stalls (per the conventions' standard injection, with the contract's silence-not-progress rule realized here: every received sidecar frame resets the bound, so a long turn streaming steadily past the bound completes — asserted — and only silence trips it): a stalled sidecar call during a send, an `interpret_document`, a stalled *spawn* (a process that starts but never reaches ready resolves within the bound to the shape-classified failure — the backend-restarting rejection window is bounded by it, never indefinite), a stalled recycle `session/load` (the affected session's reload resolves within the bound — logged and re-driven by its next attempt — with the other sessions' reloads unblocked), a stalled `endpoint_for`/`revoke`, a stalled store access, and a stalled credential probe each resolve to their classified or structured outcome within the bound — never an indefinite hang (injected stalls with the scripted fakes and injected clock).
- store: `unavailable` (`backend_state` and `pending_message` surface their error arms — never coerced to `None`/none, the destruction-on-certainty guard, asserted), `write_failure` (acceptance fails synchronously pre-acceptance; post-acceptance surfaces per contract; a resume-schedule write fault fails whole: the terminal takes the contract's manual-standing shape, nothing armed, the fault logged — asserted on all three; a fresh usage limit later re-arms normally, asserted), `corrupt_row` (error arm, preservation).
- mcp: `provisioning_fault` (synchronous pre-acceptance; internal fault after), `revoke_fault` (teardown step retries).
- clock: covered by injection in the scheduler tests.

Provisional mocks — unverified: the recorded ACP transcripts behind the fake sidecar — error shapes for auth/usage-limit/outage (with reset time), the update-kind vocabulary, structured tool-result frames, `session/load` behaviour, concurrent prompting, streamable-HTTP `mcpServers` acceptance, the interpretation reply shape, the `~/.claude` layout probe, and the spawn-time credential-caching assumption itself — that the running sidecar fixes its credentials at spawn, making a respawn both necessary and sufficient to change them, which the whole recycle design rests on. Each is a release item carried by the message-lifecycle contract; first recording replaces the project-authored transcript.
