## 1. Purpose

The HTTP surface, per the architecture: configuration, routes, live event fan-out, startup output, the service log, structured failure surfacing. The wire behaviour toward `ui` is the events contract's transport realization plus the route envelopes the contracts name — the binding contract's table, the message-lifecycle sync/async line, the evidence contract's route-owned kind declaration, and the printer-state closed sets; this document covers the transport internals.

## 2. Internals

- **HTTP stack** — axum on tokio; the UI's built assets are embedded in the binary and served statically; `mcp` mounts its endpoint routes on this listener (the same wiring `mcp`'s design doc states — one listener is the one-service deployment reality), and the listener-address value `server` hands `mcp` at wiring for endpoint-URL composition is the loopback address with the configured port — the sidecar is a local process, and endpoint URLs are for it alone, never for LAN clients; the port is the configured part, the loopback host the deliberate v1 resolution of "the service's current configured address" for the backend's local use, and the value is fixed for the process's life (the port option applies at the next start, so a change reaches `mcp` through the restart's re-wiring). The composition root also supplies the data directory — SQLite and the evidence files under the XDG data path, per the settled storage decision — to `sessions` at wiring: a fixed path, not a v1 config option.
- **Configuration** — TOML at the XDG config path with flag > env > file > default precedence (the settled decision); an *absent* config file is the normal first-run state — the chain falls through to env and defaults, never a failure. The v1 option set: `port` (default 8345), `printer_document` (the document location; no default — unset is a surfaced state, not an error, and the loaded value is handed to `printer` at startup wiring, `printer` owning the location-unset cause), and `log_path` (the log *file*: default `filamentary.log` in the XDG state directory; an operator-supplied value names the file — this is R10's documented path). Flag and env spellings derive mechanically from the option names (`--port`, `FILAMENTARY_PORT`). Startup binds the configured port on every address (R1: v1 has no bind-address option), printing one URL per bound address, each with a QR decoding to exactly that URL; every fatal startup path prints its cause before the non-zero exit — the rule is the class, not a list: any *server-owned* startup step failing (the port occupied, an address it cannot bind, an unreadable or invalid config, an emitter subscription unavailable, `mcp`'s routes failing to mount) is fatal with its distinct cause named; nothing serves degraded — with one deliberate carve-out: the log sink is diagnostics, never a dependency, so an unopenable `log_path` falls back to stderr and the service starts (the Service-log bullet's rule, exempt from the fatal class by design). Module startup work that runs after wiring is not in that class: a `sessions` recovery-scan failure leaves the service running with `sessions` owning the re-drive, per the message-lifecycle contract's composition guarantee. `server` is the composition root: it wires every module and completes all cross-module binding before any module's startup work — `sessions`' recovery scans, emitter relays, the first request — begins, per the message-lifecycle contract's composition guarantee. Configuration is read once at startup with one exception forced by the binding contract's live unset→set transition (its S3 asserts the cause change reaching a *connected* consumer, which a restart-applied setting can never do): the config surface carries a set route for `printer_document` — it persists the option to the config file and, only once that persist commits, calls `printer.set_document_location` (the printer-state contract's operation; a persist fault answers its structured envelope with nothing handed over, and a hand-over fault *after* the persist answers the retryable fault naming the hand-over with the persisted value already standing — the idempotent set route's retry is the remedy, the next startup applies the persisted value regardless, and the divergence is bounded by the user's own visible failed call, never silent); when the running value comes from a higher-precedence source (flag or env), the set route rejects with a validity error naming that source — the persisted value would be shadowed at the next start, and a setting that silently reverts is worse than a refusal. Every other option applies at the next start. The config surface's help text documenting this is `ui`'s own static content — never an envelope remedy this module synthesizes.
- **Live stream** — one SSE stream per client. Tokens are (run id, monotonic sequence); `server` alone stamps them, as it relays each event in the emitters' commit order and as it answers each fetch under that same ordering — which realizes gapless composition (single-shot and paginated alike) while the emitters and the module-internal subscription stay token-free per the events contract. One bounded replay ring for the service run holds recent durable events across all scopes in relay order — one ring, matching the one global token sequence, so a presented token's position is well-defined and replay is all-or-resync, never a partial replay of some scopes; a presented token older than the ring's tail, or carrying a different run id, draws the in-stream resync-required signal on a stream that keeps delivering. Heartbeat frames ride every stream on an idle timer.
- **Fan-out** — a registry of connected streams; durable events are relayed verbatim from the `sessions` and `printer` subscription seams (payloads and keys byte-identical, tokens added); ephemerals fan out unbuffered. The registry tracks sessions whose session-deleted event it has relayed and drops later events of *both* wire kinds for them — the deleted event itself is the last one through, the drop applying at relay, so a dropped event never enters the replay ring either: replaying and later-connecting streams inherit it identically.
- **Upload routes** — realize the evidence contract's route-owned kind declaration: the kind-specific controls' routes declare their kind (image capture/gallery → image, project → `.3mf`, gcode → gcode), and the generic first-message attachment route declares from the file's type with extension precedence for `.3mf`/`.gcode` — the rejection a file draws is fixed by which route received it.
- **Evidence read routes** — the `server → sessions` evidence reads: a gallery/transcript byte route requesting the Display variant, a download route requesting Original — the variant is route-owned, like the kind declaration; which bytes each variant yields is the evidence contract's serving rule, not decided here — and the `evidence_list` route relaying pages and their honoured-or-refused continuations verbatim. Error families pass through distinct per R10: unknown-ref, the read-failure fault class, and the reproduction fault each arrive as their own structured envelope — a stuck read is never dressed as an unknown ref and never hangs (the bounded-resolution rule).
- **Route envelopes and the sync/async line** — session routes render module answers and structured errors with their cause per R10, and the remedy where the owning contract defines one; the webcam/snapshot routes wrap `binding()` per the binding contract's `server` column; nothing is re-worded — envelopes carry the structured cause through. The message-lifecycle contract's synchronous rejections return as the route's immediate error response with the structured envelope (composer content untouched client-side); acceptance returns immediately, the turn's outcome arriving through the events transport. The manual `bind` route (the binding contract's one write on this edge) passes any name through — its synchronous rejections are exactly the contract's two, the empty-after-trim name and unknown-session — and answers with the immediately-bound state. The printers-screen route envelopes `printers()` and `reachability()` per the printer-state contract's closed sets: every member mapped, with its cause exactly where the state carries one (Pending/NeverInterpreted and Unreachable; Fresh carries the list instead, and Reachable/Unknown/NoTelemetry are causeless) — nothing fabricated, no member unmapped; `printers()`' Error arm envelopes as the transient fault class, never coerced into a freshness state. On the delegating binding states' printer-facing routes, printer-state's unknown-printer error relays with the remedy the binding contract assigns `server` to select: re-bind where the retained list judges the bound name missing, wait where the binding is simply newer than the list. The printers screen's per-printer routes extend to the rest of printer-state's read surface — telemetry (status, temperatures, position), the log views, and the config section list and reads — each route mirroring its operation with provenance, causes, and bounded-view continuations relayed intact per that contract (R6's "shown in the UI" has its surface here); these routes are session-independent, so printer-state's closed-set answers envelope plain and distinct — unknown-printer with no binding-derived remedy (that remedy exists only on session-scoped, binding-gated routes), the no-telemetry error, and unknown-section — never collapsed and never remedy-fabricated. On the binding-gated routes, the unknown-printer remedy's discriminating input is a `binding()` re-read, and every member of the re-read's closed set is mapped: still-delegating → the wait remedy, bound-but-missing → the re-bind remedy, and any other non-delegating state (unbound, pending-evaluation, bound-but-ambiguous) → that state's own binding-gate error envelope, exactly what a fresh request would draw — the binding moved under the call; a re-read fault relays the plain unknown-printer error with no remedy attached, logged.
- **Camera routes** — the user-path capture flow the architecture assigns here: the snapshot route reads the session's stored choice via the session-store contract's `camera_choice_read` (a read fault there envelopes as its own fault surface, distinct from every capture outcome), calls `printer.snapshot` with `User` as requester and that choice, hands the capture to `sessions.attach_snapshot`, and answers the new reference — every outcome distinct through its envelope: each printer-state refusal reason, the transient fetch failure, and evidence's capture-failed each carry their own structured cause, never collapsed. The webcam-listing route envelopes `webcams(printer)` with the answered-empty list (capability absent) distinct from a discovery failure, each offered camera carried with its discovery-supplied scope (the offering printer's canonical name and telemetry URL, opaque to the client); it is binding-gated per the binding contract's `server` column, like the snapshot route itself — and that column is complete as listed, so the camera-choice *set* route carries no binding gate: settability is discovery-offered per the printer-state contract, the set request carrying the offered camera *with that scope* back through, which the route passes to `sessions` — the scope is born at the discovery and travels through the client untouched, never fabricated here — and the route answers `sessions`' outcome (its unknown-session and store-fault surfaces included). On every binding-gated route, `binding()`'s failure arm envelopes as the retryable fault surface — never coerced into a binding state, per the contract.
- **Service log** — one documented path: request lines plus module-reported events, written through a logging facade every module shares; an unwritable log sink falls back to stderr and keeps serving (the log is diagnostics, never a dependency).

## 3. Interface

Public: the HTTP API consumed by `ui` — routes mirroring the contracts' operations, the session-store contract's included (list and search with the include-archived selector, transcript and session-state fetch, delete, rename, archive/unarchive, and the camera-choice set and read — behaviour, paging, and honoured-or-refused continuations all that contract's, enveloped like every other route) — and the stream. Module-private: the token stamper, replay ring, and fan-out registry, testable directly.

## 4. Error handling and failure visibility

Startup failures print to the shell and exit non-zero (R1). Route handlers translate module errors into envelopes without loss; a handler panic before the response commits is converted to a 500 envelope carrying the conventions' standard fault-class structured error — cause naming the route, retryable — no new classification, rendered by `ui` like any route-error envelope, never the message-lifecycle contract's internal-fault classification and never routed through any transcript machinery — and logged — never a 500 without a cause; a panic while a stream is already open can only end that stream, so it detaches the one client (which reconnects and resyncs) and logs the route — the same recovery path as a dropped connection, never a service-wide effect. Stream faults (a client gone mid-write) detach that client only. Emitter subscription failures at startup are fatal (the service cannot honour convergence without them); a subscription lost at runtime is re-established with a resync signal to every connected client, and logged — and the loss marks the ring: every token minted before the re-establishment draws resync from then on, so a client that was *disconnected* through the outage and reconnects later is resynced too, never served a replay that silently omits the events the outage swallowed.

## 5. Test plan

Contract tests (`test_contract_*`), unit level, with faked emitters, faked module call surfaces (`sessions`/`printer` route targets), and an injected clock:

1. Token order: sequences strictly increase across interleaved fetches and events; run id changes on restart; every pre-restart token draws resync.
2. Replay: a held token replays exactly the missed durable events, no ephemerals, idempotently re-deliverable; beyond-ring tokens draw the in-stream resync on a live stream; after a runtime subscription loss and re-establishment, a client reconnecting with a pre-outage token draws resync — never a silent partial replay (asserted).
3. Gapless composition: an event racing a fetch is on either side of the token, never neither (injected race); the same per page for a paginated fetch.
4. Fan-out fidelity: payloads and keys byte-identical to the emitter fixture through the full transport; each ephemeral kind (deltas, turn-started, turn-ended) relayed live with its session key, never buffered or replayed (asserted per kind); a plain state-fetch response carries the turn-in-flight flag (asserted mid-turn and idle); deletion-committed drops on live streams for both wire kinds, and on the replay path too — a client reconnecting with a pre-deletion token is never served a post-deletion event for that session (asserted).
5. Heartbeat: idle streams carry it on the injected clock; its absence is only ever a real disconnection.
6. Envelopes: each binding state's webcam/snapshot envelope per the contract table; the printers-screen route envelopes every freshness and reachability member with its cause exactly where the contract defines one — asserted per member, causeless members asserted causeless — and `printers()`' Error arm as the transient fault envelope, asserted distinct from every freshness member; unknown-printer on a delegating state's session-scoped route relays with the binding-derived remedy — the re-bind and wait cases each asserted via the `binding()` re-read, and a re-read fault relaying the plain error with no remedy (asserted); the session-independent per-printer routes envelope unknown-printer (remedy-free), no-telemetry, and unknown-section plain and pairwise distinct (asserted); a structured module error's cause survives into the envelope for each error family, and the remedy too exactly where its contract defines one on a synchronous answer (binding's verdicts, evidence's remedies) — never fabricated where none exists; message-lifecycle's classifications are asynchronous failure entries riding fan-out (test 4's fidelity), never route envelopes.
7. Configuration precedence: flag > env > file > default per option over the enumerated v1 set (port, printer_document, log_path); an absent config file falls through and the service starts (asserted distinct from unreadable); unset location surfaced as state, and the location set route persists the option then calls the faked `printer`'s `set_document_location` (asserted on both effects and their order, plus the write-fault envelope, the hand-over-fault answer with the persist standing, and the shadowing rejection naming the overriding flag or env source — each asserted distinct); invalid TOML is a startup failure naming the path, distinct from an unreadable config file (the fault class, also naming the path).
8. Startup: occupied port exits non-zero with the R1 message; success prints one URL per bound address, each QR decoding to exactly its own URL (asserted on output, per address).
9. Kind declaration: each kind-specific route declares its kind; the generic route declares by type with extension precedence — the same PDF drawing unsupported-format via the image route and unsupported-kind via the generic route, and `part.gcode` accepted there (asserted per route).
10. The sync/async line at the routes: each synchronous rejection family returns as the immediate structured error response; an accepted send returns immediately with no failure in the response (asserted per family against the faked module surface).
11. The bind route: any name passes through and answers immediately-bound; the empty-after-trim and unknown-session rejections each return as their immediate structured response; a store-fault answer relays the failure surface (asserted); the rename route's empty-after-trim rejection likewise returns as its own structured response, asserted distinct from a store fault.
12. Startup failures: occupied port, unbindable address, unreadable config, an unavailable emitter subscription, and `mcp`'s routes failing to mount each exit non-zero naming their distinct cause (asserted on output); a handler panic answers a 500 envelope with the server-fault cause naming the route (asserted); composition-root ordering — no module startup work (recovery-scan calls on the faked `sessions` included) begins before all cross-module wiring completes (asserted on call order against the fakes); a recovery-scan failure leaves the service serving — the carve-out from the fatal class asserted here, not only at the contract's integration level.
13. Evidence read routes: the gallery/transcript route requests Display and the download route Original (asserted on the faked call surface); `evidence_list` pages relay with continuations honoured, and a refused prior-run continuation arrives as its explicit refusal, never an empty page; unknown-ref, the read-failure fault class, and the reproduction fault each arrive as their distinct envelope — asserted pairwise distinguishable; the session-list, search, and transcript-fetch routes relay their paging with a refused prior-run continuation arriving as its explicit refusal (asserted per route), list and search honouring the include-archived selector (asserted); the telemetry, log, and config routes relay provenance, causes, and bounded-view continuations intact per printer-state (asserted per family).
14. Camera routes: the capture flow reaches `printer.snapshot` with requester `User` and the session's stored choice, then hands the capture to `sessions.attach_snapshot` with its provenance — camera and capture time — intact and unmodified (asserted on content at the faked surface, nothing attached on refusal); each printer-state refusal reason, the transient fetch failure, and capture-failed arrive pairwise distinguishable through the envelope (asserted); the webcams route answers the empty list distinct from a discovery failure; the webcams route gates on `binding()` per the contract's `server` column (asserted per non-delegating state), and each offered camera carries its discovery-supplied scope; the camera-choice set route carries no gate — asserted accepted in a non-delegating state given an earlier offering, the stored scope asserted equal to the discovery's, passed through never fabricated — answering `sessions`' outcome; `binding()`'s failure arm on a gated route envelopes as the retryable fault, asserted distinct from every binding state.

Failure-mode tests (`test_failure_<dependency>_<mode>`):

- sessions/printer emitters: `subscription_lost` (re-established + resync signal, logged), `subscription_unavailable_at_startup` (fatal, R1 path), `open_stall` (a stalled subscription open resolves within its bound — at startup to the fatal path with its printed cause, at runtime re-establishment to a retry with the resync signal — never an indefinite hang, injected).
- sessions/printer call surfaces: `route_target_fault` per family across every route — creation (a storage or provisioning fault, asserted retryable-fault distinct from every validity rejection), send, retry, bind, upload and snapshot-attach (each fault class of the evidence contract's intake reaching its route enveloped), delete/rename/archive/search, session listing and session state/transcript fetch, evidence reads and listings, webcam listing and snapshot, camera-choice set and read (the read's fault distinct from every capture outcome), the location set, printers, telemetry, log and config views — each reaching its route as the envelope with cause intact, never a 500 without one; `unknown_session` asserted per session-scoped route family; `stall` (bounded, injected).
- log sink: `unwritable` (stderr fallback, service keeps serving).
- config file: `absent` (falls through to env and defaults, the service starts — never a failure), `unreadable` (the fault class, startup failure naming the path), `invalid_content` (malformed TOML, the validity class, startup failure naming the path), and `write_failure` (the location set route's persist failing — an unwritable file or directory — answers the structured fault envelope with nothing handed to `printer`, asserted) — all asserted distinct.
- OS listener: `port_occupied` and `address_unbindable` (the environment fault class behind contract tests 8 and 12 — each exiting non-zero with its distinct cause).
- client connections: `gone_mid_write` (that stream detached, others untouched), `panic_mid_stream` (an injected handler panic on an open stream detaches that one client, others and the service untouched, the route logged — asserted), `open_stall` (a stalled stream-open resolves to an open stream or a structured error within its bound — never an indefinite hang, injected).
- mcp mount: `mount_failure` (fatal startup path, distinct cause, non-zero exit — asserted).
- clock: covered by injection in heartbeat/stream tests.
